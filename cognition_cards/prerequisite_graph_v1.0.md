## 设计说明

### hard vs soft
- **hard**：不理解先修就无法理解本卡片。比如不理解复利就无法理解为什么年化超10%要做好亏光准备。
- **soft**：理解先修对理解本卡片有帮助但非必须。比如有应急金对失业后学短视频有帮助，但不是硬门槛。

### 传递约简
只保留直接先修关系。如果A→B→C已经存在，不建A→C的冗余边。调用引擎沿先修边回溯时会自动遍历间接先修。

### 自适应回溯（调用引擎v0.3待实现）
当用户问一个复杂问题时：
1. 匹配到高级卡片（如C-005年化超10%亏光本金）
2. 检查该卡片的hard先修（M-021复利、P-058高息陷阱）
3. 如果用户的问题显示可能不理解先修，自动回溯到基础卡片先解释
4. 输出：基础概念解释 → 高级案例 → 行动建议
