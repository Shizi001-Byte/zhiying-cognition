## 一、v0.6 改了什么

### 1. 修复 v0.5 的核心 Bug：source_card 事后反查失败

**v0.5 的问题代码**：
```python
# 事后反查这条建议来自哪张卡片
source_card = None
for m in matches[:3]:
    dos = m['card'].get('行动建议', {}).get('做什么', [])
    if isinstance(dos, list) and act in [str(d).strip() for d in dos]:
        source_card = c
        break
if source_card and is_semantically_relevant(...):
    filtered_actions.append(act)
elif not source_card:
    filtered_actions.append(act)  # ← 找不到来源就保留
```

三个阶段出错：
1. `dos` 可能是字符串而非列表 → 整个 if 跳过 → source_card=None
2. 字符串比较 `act in [...]` 受 strip/编码影响 → 匹配失败
3. **兜底逻辑"找不到来源就保留"** → 不相关内容必定漏过

实测后果：「月薪6000欠5万」场景混入 C-005 的"年化超10%做好亏光本金准备"（来自P2P暴雷案例，和债务问题无关）。

**v0.6 的修复**：收集时就记录来源，不做反查。
```python
all_action_src.append((str(d).strip(), m['score'], card.get('卡片ID')))
```
来源是该条建议的**直接生产者**，零匹配失败可能。

### 2. 过滤门槛提高

| 条件 | v0.5 | v0.6 |
|------|------|------|
| 含问题核心词 | 保留 | 保留 |
| Top1卡片自身建议 | 保留 | 保留 |
| 含Top1法则关键词 | 命中1个即保留 | **需命中≥2个** |
| 与Top1同周期 | 保留（宽松） | **取消该条件** |
| 找不到来源 | 保留（漏洞） | 不可能发生 |

原则：**宁可少给，不给错**。

### 3. 关键词映射修正：「闲钱」

```python
# v0.5
'闲钱': ['闲钱', '资产配置', '应急基金', '指数基金', '定投']
# v0.6
'闲钱': ['闲钱', '复利', '储蓄', '应急基金', '资产配置']
```

原因："指数基金"和"定投"太泛，会命中房产卡片（P-019的核心法则里含"不如买指数基金"），导致"10万闲钱怎么理财"的Top1错成"自住房不算投资"。

**关键认知：v1.6 的"标题0异常"是假达标。** 当时判断标准只查了"长度<6"和"以——开头"，漏掉了"以逗号开头""以'的时候/现在他/我认识一个'开头""末尾单字截断"。v1.7 用严格标准重查，发现11张 + 3张漏网 = 14张。

**教训：检测标准宽松 = 假达标。** 质量门禁的价值不在"通过"，在"标准是否够严"。

## 五、剩余问题（v0.7 方向）

1. **场景5"30岁还没理财"匹配不够针对**：理想应是"种一棵树最好的时间是10年前"（P-058），当前匹配M-026巴比伦储蓄（合理但不够戳心）。需在关键词映射中加"来得及/太晚/晚了"→ 匹配P-058。
2. **v1.7 的12张"原文未明确列出禁区"**：都是P1/P2级案例卡，原始资料确实没写禁区。可选方案：从同类型卡片迁移通用禁区，或保持诚实标注。
3. **详细解释本身是片段**：P-050/P-055/P-056 的详细解释只有2-3行（原始认知池抓取时被截断）。需要回到7528条认知池做二次全文回溯。
4. **P2级卡片占比仍高**：76张里P2级13张，内容质量相对弱。
